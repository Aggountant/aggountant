# Skill rebuild: SOUL as the one home of house rules and of how to read the tool

## Description

Skill rebuild, step 1 (after `skill-writing-principles`). `aggountant-init/SOUL.md`
is read before every task. Its role description is good and stays. Its tools
part is a partial command list that goes stale with every slice (it lacks the
bank import, fiscal year, `home upgrade` and the year-end close) and has
become the place slices put reminders. The house rules of the company home
are meanwhile written into three skills.

## Wanted

SOUL becomes the one home of what applies to every task, at about 500 words:
the role as it is; the house rules once (`AGENTS.md` routes and practices,
`TODO.md` pending work, `knowledge company` sourced facts, `obligation` the
program's own list, secrets in none of them, commit with the change when the
home is a git repository); what is permanent (seal, close, filing) and why the
user approves it from what they see; how to read the tool (`--help`, `--json`,
`error_code`, `message`, `next_command`, previews are free). The command list
goes. Only SOUL is edited; the task skills drop their copies in their own
rebuild slices.
