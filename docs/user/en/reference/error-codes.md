# Error codes

When a command fails, aggountant gives an error code, which appears as it is
in the agent's output. Most errors are deliberate stops: the program refuses
to do something that would make the books wrong, and the books stay as they
were. The table has the most common codes and what to do about each.

## How an error shows

A failed command prints the error like this:

```json
{"error_code":"PERIOD_SEALED","error_kind":"user","message":"PERIOD_SEALED: period 2026-03 is Sealed; corrections go to the next open period","hint":"kirjaa seuraavalle avoimelle kaudelle"}
```

- `error_code` is a stable code that tells the agent what to do.
- `error_kind` is `user` when the cause is in the input or the state of the
  books and can be fixed (exit code 1), or `system` when the cause is in the
  environment, such as a file or a connection (exit code 2).
- `message` describes the cause in words.
- `hint` is the "Mitä tehdään" (what is done) column of the table below, in
  Finnish. It is present only for codes the table lists.
- `test_seam` is present only when
  [the test variable `AGGOUNTANT_BROKER_SCRIPT` answered for the authority](../troubleshooting.md#a-return-was-marked-filed-although-nothing-was-sent).

The agent gets a code's whole explanation with `aggountant explain CODE`
(`--lang en` for English). The program reads the explanations from this page,
so they are the same as below.

The Vero.fi readiness blocker codes (`VERO_…`) have their own page:
[Vero.fi readiness blockers](vero-fi-blockers.md).

## Codes

| Code | What happened | What is done |
|---|---|---|
| `ACCOUNT_NOT_FOUND` | an entry refers to an account that is not in the chart of accounts | the agent picks an account from the chart |
| `ALREADY_INITIALIZED` | setting up a home was run on an existing home | nothing, because the home already exists and was not touched |
| `APPROVAL_REQUIRED` | an entry was attempted without an approved preview | the agent shows a preview first, and you approve it |
| `BANK_ENTRY_POSSIBLY_BOOKED` | a voucher recorded outside statement import (for example a manual entry) may already record a new statement transaction: its identifier or description contains the bank's reference, or it records the same amount on the same side of the same bank account within 7 days; nothing was sealed | if the voucher records the transaction, link the transaction to it instead of a new voucher; if not, mark that it does not record it; the error's `details` names the transaction and the voucher ([Import the bank statement](../tasks/import-bank-statement.md#when-bank-transactions-were-recorded-by-hand-before)) |
| `BANK_VOUCHER_MISMATCH` | a statement transaction was linked to a voucher that does not record it (different bank account, amount, side or date), the voucher is already linked to another transaction, or the transaction is already linked to another voucher; nothing was sealed | check the voucher number (`voucher show`) ([Import the bank statement](../tasks/import-bank-statement.md#if-something-goes-wrong)) |
| `CAPTURE_VAT_CLASS_UNKNOWN` | the receipt proposal names a VAT rate class that aggountant does not know; nothing was recorded | the agent chooses the class that matches the receipt's VAT treatment; the message lists the classes a purchase can use |
| `CAPTURE_PREPARATION_CHANGED` | the receipt details, the proposal or the chart of accounts changed after approval | the agent makes a new preview, and you approve it ([Sealing and approval](../concepts/sealing-and-approval.md)) |
| `CLAIMANT_FACT_CONFLICT` | a fact about an expense claimant contradicts a fact already recorded for the same days, for example two primary regular workplaces; nothing was recorded | correct the old fact (`claimant correct`) instead of adding a new one ([Record your regular workplace](../tasks/record-regular-workplace.md#when-a-fact-changes-or-was-wrong)) |
| `CLAIMANT_RELATIONSHIP_UNKNOWN` | no relationship to the company is recorded for the person on the trip date, so no tax-free travel allowance is computed | tell the agent whether the person is, for example, an employee, the managing director or a board member, and from which date ([Record your regular workplace](../tasks/record-regular-workplace.md)) |
| `CLOSE_CONTENT_CHANGED` | the content the close showed for approval has changed since the approval opened | reject the close and start it again ([Close the month](../tasks/close-month.md)) |
| `CONTRACTOR_NOT_CLAIMANT` | an invoicing contractor or consultant was to be recorded as an expense claimant | a contractor's travel costs belong on their own invoice, not on an expense claim |
| `EMPLOYER_REGISTER_MISMATCH` | the first month given for the separate report disagrees with the employer register in YTJ; nothing was written | check the comparison; use the register's month, or confirm your own month to the agent ([File the employer's separate report](../tasks/file-employer-report.md#set-up-the-separate-report-once)) |
| `EMPLOYER_REPORT_ALREADY_FILED` | the month already has an employer's separate report that Tulorekisteri accepted | do not file a new report; correct it with a replacement report ([File the employer's separate report](../tasks/file-employer-report.md#if-something-goes-wrong)) |
| `EMPLOYER_REPORT_FILED_OUTSIDE` | an imported transcript 630 shows the month already reported outside aggountant | do not file a new report; correct the report in the e-service or record its reference first ([File the employer's separate report](../tasks/file-employer-report.md#when-an-earlier-payroll-service-filed-reports)) |
| `EMPLOYER_REPORT_INVALID_EVIDENCE` | the e-service evidence given with `complete-manual` does not settle the month: the report reference is not 32 characters long, or for an uncertain replacement the version is missing or not newer than the replaced one | give the references and the version the e-service shows. An old version there means the replacement has not arrived, and the month keeps waiting. If the replaced version was not recorded, ask for the state with `file-wage employer-report status` |
| `EMPLOYER_REPORT_INVALID_SETTINGS` | the separate report settings have a pension insurance whose provider code or policy number the report does not accept | check the pension company code and the policy number |
| `EMPLOYER_REPORT_NOT_CONFIGURED` | the Tulorekisteri profile has no separate report settings | set up the separate report ([File the employer's separate report](../tasks/file-employer-report.md#set-up-the-separate-report-once)) |
| `EMPLOYER_REPORT_NO_REFERENCE` | the month to replace is known only from transcript 630, which has no report reference | replace the report in the e-service, or record its reference first (`complete-manual`) |
| `EMPLOYER_REPORT_PREVIOUS_STATED_NEEDLESSLY` | the previous report's pension insurances were stated, but aggountant already knows them (it sent the report) or nothing is being replaced | leave out `--previous-pension-insurance` and `--previous-no-pension-insurance` |
| `EMPLOYER_REPORT_PREVIOUS_UNKNOWN` | the report to replace was given outside aggountant and only its reference was recorded, so its pension insurances, which a replacement must repeat, are not known | read them from the report in the e-service and give them (`--previous-pension-insurance`, or `--previous-no-pension-insurance`), or correct the report in the e-service ([File the employer's separate report](../tasks/file-employer-report.md#when-an-earlier-payroll-service-filed-reports)) |
| `EMPLOYER_REPORT_OUTCOME_UNKNOWN` | the outcome of an earlier sending for the month is still unclear | ask for the state (`file-wage employer-report status`), do not send again ([When something goes wrong](../troubleshooting.md#the-outcome-of-a-filing-is-uncertain)) |
| `EMPLOYER_REPORT_PAYMENTS_CONFLICT` | "No wages payable" was reported for a month that has a travel allowance report | report the month as having only travel allowances |
| `EMPLOYER_REPORT_REPLACEMENT_NOT_ALLOWED` | a replacement report would change the pension insurance details | cancel the report in the e-service and send a new one there |
| `EMPLOYER_REPORT_STATUS_UNKNOWN` | Tulorekisteri gave no final state | ask again later or check the e-service; do not send again |
| `EMPLOYER_REPORT_TRANSCRIPT_CONFLICT` | imported transcripts 630 disagree about the month | check the month in the e-service and record the report reference (`complete-manual`) |
| `EMPLOYER_REPORT_WAGES_UNSUPPORTED` | wages were paid in the month, and aggountant does not compute the health insurance contribution | file the report in the e-service ([What is ready and what is not](status.md#tulorekisteri-and-employees)) |
| `FISCAL_YEAR_CONFLICT` | a fiscal-year definition would move recorded vouchers or a closed year to another fiscal year | read the message; a definition cannot change what has already been recorded |
| `FISCAL_YEAR_UNDEFINED` | the date is before the company's first fiscal year, or no fiscal year ends in the given year | check the date or the year; `fiscal-year list` shows the definitions |
| `GATE_NOT_OPEN` | the approval has already been answered or is not open | ask the agent to show the run's state |
| `HOME_NOT_INITIALIZED` | the command's home path holds no home set up with `init`; nothing was written | the message names the path and how it was chosen. If the home or the directory is wrong, fix the path ([When something goes wrong](../troubleshooting.md#vouchers-seem-to-have-disappeared)). Run `init` only for a new company |
| `IMPORT_PREPARATION_CHANGED` | the bank statement, the proposed entries, the actor or the chart of accounts changed after the import preview; nothing was sealed | the agent makes a new preview, and you approve it ([Import the bank statement](../tasks/import-bank-statement.md)) |
| `INVALID_CAMT` | the statement file is not a readable camt.053 or camt.052 statement: the XML is broken, the account IBAN or a transaction field is missing, or it has a transaction the program cannot import (for example a batched transaction); nothing was written | read the message and get the right file from the bank ([Import the bank statement](../tasks/import-bank-statement.md)) |
| `INVALID_FISCAL_YEAR` | the fiscal year is longer than 18 months, does not start on the first or end on the last day of a month, or does not follow the earlier fiscal years | correct the dates (Accounting Act 1:4) |
| `INVALID_INPUT` | the input has the wrong shape or an unknown field | the agent fixes the input |
| `MASTERDATA_CORRUPT` | the home's chart of accounts, its version or the VAT roles are missing or disagree with each other | if the program was just upgraded, run `home upgrade --dry-run` and then `--apply` ([Upgrade aggountant](../tasks/upgrade.md)); otherwise a file was edited by hand, so restore it from version control |
| `MASTERDATA_NOT_INITIALIZED` | the home has no chart of accounts | check the home: it is the wrong one or has not been set up ([When something goes wrong](../troubleshooting.md#vouchers-seem-to-have-disappeared)) |
| `MISSING_ASSIGNMENT` | a transaction on the bank statement has no entry, so the whole statement was rejected | the agent completes the entries ([Import the bank statement](../tasks/import-bank-statement.md)) |
| `NATURAL_KEY_ALREADY_SEALED` | warning from `voucher validate`: the same content has already been sealed under this `natural_key` | nothing; sealing returns the existing voucher and writes nothing new. Do not change the key to get past it |
| `OPEN_OBLIGATION` | an open obligation blocks the period's close | deal with the matter and mark the obligation resolved ([Periods](../concepts/periods.md#obligations)) |
| `OUTPUT_EXISTS` | the report file already exists | give a new file name |
| `PERIOD_CLOSING` | the period's close is in progress | if the voucher belongs to this period, reject the close and record it; otherwise record it in the next period ([Close the month](../tasks/close-month.md)) |
| `PERIOD_NOT_SEALED` | a VAT return was attempted for a period that has not been closed, or a report needs the previous fiscal year's closing balances and that year has not been closed | close the period or the previous fiscal year first. The new fiscal year's monthly report waits for the previous year's year-end close, but recording, month closes and VAT returns do not ([Prepare the financial statements](../tasks/year-end.md)). If the previous fiscal year holds only the opening balances from setup, see how to date them in [Set up your company's books](../start/set-up-company.md) |
| `PERIOD_SEALED` | the period is closed, or the date falls in a closed fiscal year or one before it | record it in the next open period |
| `PERIOD_TRANSITION_CONFLICT` | the period's state does not allow the requested change: for example the period has already been filed, another close is in progress, months and quarters are being mixed in the same year, or a quarter is being closed in a fiscal year that is not the calendar year | read the message. A filed period is not filed again; it is corrected with a replacement return ([Correct a return that has been filed](../tasks/file-vat-direct.md#correct-a-return-that-has-been-filed)) |
| `PLACE_REPLACED` | the expense claimant's place was replaced by a corrected place and can no longer be referred to | use the new place the message names ([Record your regular workplace](../tasks/record-regular-workplace.md#when-a-fact-changes-or-was-wrong)) |
| `POSTING_PROJECTION_CHANGED` | a statement transaction is already recorded with the same bank facts, but its assignment is now different (account, amount, VAT, date or description); nothing was sealed | give the transaction the assignment its voucher was sealed with (`voucher show`); if the earlier entry was wrong, it is corrected with a new voucher ([Import the bank statement](../tasks/import-bank-statement.md#if-something-goes-wrong)) |
| `REGULAR_WORKPLACE_UNKNOWN` | no regular workplace is recorded for the person on the trip date, so no tax-free travel allowance and no travel costs are computed | tell the agent where you work permanently and from which date ([Record your regular workplace](../tasks/record-regular-workplace.md)) |
| `RUN_NOT_FOUND` | the run cannot be found | check that the command hit the right home |
| `SECONDARY_WORKPLACE_INVALID` | the place cannot be a secondary workplace: it is not premises of your company or its group company, it is in the same municipality as the primary regular workplace, or no primary regular workplace is recorded | record a place in the same municipality as another regular workplace, or record the primary regular workplace first |
| `SKILL_RENAMED` | the skill has been renamed; the old name is no longer installed or printed (for example `migrate-books` is now `migrate`) | use the new name the message and `details` give ([Install aggountant and its skills](../start/install.md)) |
| `SOURCE_FACTS_CHANGED` | a statement transaction is already recorded, but the bank's facts about it (amount, date, direction, party, message or status) differ from before; nothing was sealed | find out from the bank or the statements what changed before recording anything for the transaction; the error's `details` names the transaction and its voucher ([Import the bank statement](../tasks/import-bank-statement.md#if-something-goes-wrong)) |
| `SOURCE_IDENTITY_UNKNOWN` | a voucher already holds the statement transaction's reference, but it cannot be compared because the transaction is not found in the statement attached to that voucher; nothing was sealed | the transaction is not recorded again, and the statement cannot be imported until the case is resolved; check the voucher (`voucher show`) and its attachment ([Import the bank statement](../tasks/import-bank-statement.md#if-something-goes-wrong)) |
| `TAX_PAYEE_IBAN_MISMATCH` | the Tax Administration account in the VAT return input differs from the one in the company's stored payment details; nothing was started | leave the account out of the input, or correct the stored account to match OmaVero ([Store the Tax Administration payment details once](../tasks/file-vat-direct.md#store-the-tax-administration-payment-details-once)) |
| `TAX_PAYEE_IBAN_MISSING` | the VAT payment proposal has no Tax Administration account: none is stored and none was given in the input; nothing was started | store the account from OmaVero in the company's payment details ([Store the Tax Administration payment details once](../tasks/file-vat-direct.md#store-the-tax-administration-payment-details-once)) |
| `TAX_PAYMENT_DETAILS_CHANGED` | the company's Tax Administration account or VAT reference changed after the run prepared its payment proposal, so the return was not approved; nothing was sent | reject the run (`file-vat approve-filing --answer reject`) and start a new one, whose payment proposal takes the corrected details |
| `TAX_PAYMENT_DETAILS_CORRUPT` | the file `masterdata/tax-payments.json` is not valid, for example it was edited by hand and a reference's check digit does not match | store the payment details again (`tax-payments set`) or restore the file from version control ([Store the Tax Administration payment details once](../tasks/file-vat-direct.md#store-the-tax-administration-payment-details-once)) |
| `TAX_PAYMENT_DETAILS_INVALID` | the payment details have a reference or account number whose check digits do not match, an account that cannot be a Tax Administration account, or the same reference twice; nothing was stored | check the field the message names against OmaVero; a reference is given without spaces |
| `TAX_PAYMENT_REFERENCES_MIXED` | the payment details have both the general tax reference and tax-specific references; nothing was stored | store only the way the company pays its taxes: the Tax Administration advises using either the general reference or the tax-specific references ([Store the Tax Administration payment details once](../tasks/file-vat-direct.md#store-the-tax-administration-payment-details-once)) |
| `TAX_PAYMENT_REFERENCE_MISSING` | the VAT payment proposal has no reference: the company's payment details have neither the general tax reference nor the reference for self-assessed taxes; nothing was started | store the reference VAT is paid with, from OmaVero ([Store the Tax Administration payment details once](../tasks/file-vat-direct.md#store-the-tax-administration-payment-details-once)) |
| `TRANSCRIPT_UNKNOWN_HEADER` | the file to import is not a Finnish-language transcript 630 from the Tulorekisteri e-service with the known columns | order transcript 630 again in Finnish; nothing was stored ([File the employer's separate report](../tasks/file-employer-report.md#when-an-earlier-payroll-service-filed-reports)) |
| `TRAVEL_INPUT_INVALID` | the trip's details are contradictory or malformed (for example a return before the departure, or a drive outside the trip); nothing was computed | the agent corrects the trip's details; the message names the trip and the field ([Compute the tax-free allowances of a trip](../tasks/compute-travel-allowances.md)) |
| `TRIP_TO_HOME` | the person's home was given as a trip destination; returning home is part of a trip, not its destination | give as destinations the places where work was done on the trip |
| `TULOREKISTERI_NOT_READY` | the Tulorekisteri channel is not ready to send: the profile is missing, not in production mode or lacks your confirmation of the reporting permission, or the credential file or certificate is not in order; the message names each missing requirement | `tulorekisteri status` lists them offline and names an owner for each (`human`: your confirmation, certificate or e-service step; `agent`: a setting). The agent fixes its own with `tulorekisteri configure` ([Report travel allowances to Tulorekisteri](../tasks/report-travel-allowances.md)) |
| `TULOREKISTERI_REJECTED` | the status query confirmed that Tulorekisteri rejected the report; the run stays waiting for attention and `run show` shows the rejection | find the error in the e-service; a rejected travel allowance report is made there and recorded (`complete-manual`), a rejected correction is previewed again ([When something goes wrong](../troubleshooting.md#tulorekisteri-rejected-the-report)) |
| `VAT_ACCOUNTS_UNRECONCILED` | a VAT account has postings without a VAT code, and tax would be missing from the return | before the close, record a correcting voucher in the same month ([Close the month](../tasks/close-month.md#before-you-start)); after the close, file in OmaVero with corrected figures; if the postings do not belong in the return, give the reason ([File the VAT return in OmaVero](../tasks/file-vat-omavero.md#if-something-goes-wrong)) |
| `VAT_CURRENCY` | the VAT return figures cannot be formed; also when the period's VAT is negative because of corrections | see [What is ready and what is not](status.md#vat-return) |
| `VAT_FIGURES_MISMATCH` | the VAT return figures do not match the books | the agent uses the preview's figures |
| `VAT_FILING_UNRESOLVED` | an earlier filing of the same period may have got through, and the Tax Administration has not yet answered "not found" twice at least one bank day apart, or `run resume` was refused for a VAT return run whose sending may have begun; nothing was sent | the agent asks with `file-vat reconcile`, or first with `file-vat status` when the earlier run was interrupted while sending ([Uncertain outcome](../concepts/filings.md#uncertain-outcome), [interrupted filing](../troubleshooting.md#a-vat-filing-was-interrupted-while-sending)) |
| `VAT_INTERRUPTED_BEFORE_FILING` | shown on the `reconcile` step in `run show` of a VAT return run that stopped before anything was sent and was then resumed; the run is `not_filed` | nothing to do for that run; file the period with a new run if it is not filed yet ([A run was interrupted](../troubleshooting.md#a-run-was-interrupted)) |
| `VAT_PAYMENT_ROUTE_UNAVAILABLE` | a VAT payment was approved or retried, but aggountant has no payment connection on this route; nothing was recorded | pay the tax yourself with the OmaVero reference; the agent ends the run with `file-vat user-pays` ([The VAT return run waits for payment](../troubleshooting.md#the-vat-return-run-waits-for-payment)) |
| `VAT_PERIOD_NOT_FILED` | a replacement return, or a voucher correcting a return (`corrects_vat_period`), was attempted for a period whose VAT return has not been filed | record the correction in the period itself or reopen the period, and file the period with a first return. A replacement return applies only to a filed return ([Correct a return that has been filed](../tasks/file-vat-direct.md#correct-a-return-that-has-been-filed)) |
| `VAT_PERIOD_NOT_SEALED` | shown in the VAT return preview of a month that is not closed yet: the figures are a draft for checking and cannot be filed (`fileable: false`) | check the VAT reconciliation, correct what it finds, and close the month ([Close the month](../tasks/close-month.md)) |
| `VAT_POSTING_UNTAGGED` | warning from `voucher validate`: a posting on a VAT account has no VAT code, so the VAT return would leave its tax out | put the VAT code on the line that carries the VAT base before approval, unless the posting is a VAT payment or another transfer that does not belong in the return |
| `VAT_RECONCILIATION_ACK_MISMATCH` | the acknowledgement has no reason, its voucher numbers differ from the preview's, or there is nothing to acknowledge | the agent uses the preview's voucher numbers |
| `VAT_REPLACEMENT_CHANGES_NOTHING` | shown in the message of a failed `file-vat replace` (its `error_code` is `PROCESS_STORE`): the Tax Administration already holds the same figures, so there is nothing to replace; nothing was sent | if the replacement return was made in OmaVero, record it (`file-vat complete-manual --replacement`); otherwise check what was to be corrected |
| `VAT_REPLACEMENT_DUE` | shown in the VAT return preview of a month that has been filed: a voucher correcting the return was sealed for the month after its latest filing, so the return in force does not match the books | make a replacement return ([Correct a return that has been filed](../tasks/file-vat-direct.md#correct-a-return-that-has-been-filed)) |
| `VAT_SETTLEMENT_ROLES_MISSING` | shown in the VAT return preview beside `VAT_ACCOUNTS_UNRECONCILED`: the vouchers' chart of accounts has no settlement accounts marked, so VAT payments and refunds cannot be recognised | upgrade the home's master data and preview again, or acknowledge the payments ([File the VAT return in OmaVero](../tasks/file-vat-omavero.md#if-something-goes-wrong)) |
| `VAT_STATUS_UNKNOWN` | the VAT return's status could not be read from the Tax Administration (connection, credentials or readiness) | with an acknowledgement the return has still been filed; for an interrupted filing nothing was changed. Query again later, do not send again ([The return does not show in OmaVero](../troubleshooting.md#the-return-does-not-show-in-omavero)) |
| `VAT_TREATMENT_CLASS_MISMATCH` | the VAT treatment and the rate class do not belong together, for example `domestic-input` with `eu-goods`, `eu-services` or `zero-rated`. Those are classes of zero-rated sales, and the purchase would be recorded without VAT; nothing was recorded | the message names the treatment that fits. An EU purchase is `reverse-charge` with `scope` `eu-goods` or `eu-services` and the domestic class whose rate applies to the purchase in Finland (e.g. `domestic-standard`). A purchase with no Finnish VAT is `no-vat`; so is a service bought from another EU country whose supply the Finnish VAT Act exempts (e.g. an insurance or financial service). An exempt intra-Community acquisition of goods is `{"type":"reverse-charge","rate_class":"zero-rated","scope":"eu-goods"}` with no `deductibility` member ([How the VAT treatment is decided](../concepts/vat-treatment.md#purchases-from-another-eu-country)) |
| `VERO_NOT_READY` | direct filing readiness is not in order | see [Vero.fi readiness blockers](vero-fi-blockers.md) |
| `VERO_TEST_NOT_READY` | `vero-fi verify --target test` was refused because readiness for the test environment is not in order, for example the credential is for the production target | the message names the blockers ([Vero.fi readiness blockers](vero-fi-blockers.md)); the test verification is optional and production does not need it |
| `VERO_VAT_PERIOD_NOT_FILEABLE` | shown in the message of a failed `file-vat start` (its `error_code` is `PROCESS_STORE`) and on the run's `reconcile` step in `run show`: the Tax Administration shows the VAT period in a state other than unfiled or missing, for example already filed; nothing was sent | check the period in OmaVero; after the cause is fixed, start a new run instead of retrying the same one |
| `VERO_VAT_RETURN_NOT_PROCESSED` | shown in the message of a failed `file-vat replace` (its `error_code` is `PROCESS_STORE`): the Tax Administration has not yet processed the period's return in force; nothing was sent | wait for the processing and start the replacement return again later |
| `VOUCHER_NOT_FOUND` | there is no voucher with the given number | check the number or the home |
| `WAGE_CORRECTION_ALREADY_SENT` | the same correction has already been sent and Tulorekisteri rejected it | fix the cause of the rejection and preview the correction with a new timestamp |
| `WAGE_CORRECTION_HASH_MISMATCH` | the approved checksum does not match the correction: the report, the timestamp, the personal identity code or the version in the register changed after the preview | the agent makes a new preview, and you approve it |
| `WAGE_CORRECTION_INVALID` | the correction cannot be built: the replacement report is invalid or missing, or a report was given for a cancellation | the agent corrects the input |
| `WAGE_CORRECTION_INVALID_EVIDENCE` | the e-service evidence cannot record the correction: the reference is not a 32-character reference or belongs to another report, or the version is not newer than the recorded one | check the report reference and the version in the e-service |
| `WAGE_CORRECTION_NOT_ACCEPTED` | the report to correct is not accepted as far as aggountant knows | settle the original report first (`run show`, `file-wage reconcile`) |
| `WAGE_CORRECTION_OUTCOME_UNKNOWN` | the outcome of an earlier correction is still unclear | ask for the status (`file-wage correction status`), do not send again |
| `WAGE_CORRECTION_REPLACEMENT_NOT_ALLOWED` | the replacement would change the payer, the income earner, the payment date or the earning period | cancel the report (`--action cancel`) and make a new one ([Report travel allowances to Tulorekisteri](../tasks/report-travel-allowances.md#correct-an-accepted-report)) |
| `WAGE_CORRECTION_REPORT_CANCELLED` | the report is cancelled and has nothing to correct | make a new report with its own identifier if one is needed |
| `WAGE_CORRECTION_STALE_TIMESTAMP` | the correction's timestamp is more than a day from the moment of sending | the agent makes a new preview with the current time, and you approve it |
| `WAGE_CORRECTION_STATUS_UNKNOWN` | Tulorekisteri gave no final status for the correction | ask again later or check the e-service; do not send again |
| `WAGE_CORRECTION_UNCHANGED` | the replacement would be the same as the report in the register | nothing to send; check what needed correcting |
| `WAGE_REPORT_ALREADY_ACCEPTED` | `file-wage complete-manual` was given for a report Tulorekisteri has already accepted; nothing was recorded | the correction is made with `file-wage correction` ([Report travel allowances to Tulorekisteri](../tasks/report-travel-allowances.md#correct-an-accepted-report)) |
| `WORKFLOW_VERSION_MISMATCH` | a run in progress was started with an older version of the program | see [Upgrade aggountant](../tasks/upgrade.md) |
| `WORKPLACE_BASIS_MISMATCH` | the workplace basis does not fit the role or the place, or basis `other` has no explanation | the agent chooses a basis that fits (`aggountant claimant add --help`) or writes the explanation |
| `YTJ_UNAVAILABLE` | the YTJ open data did not answer the registration query | the registration is unknown, not absent; try later or look it up on ytj.fi |

If a code is not in the table, `message` gives the cause. Ask the agent to explain it.
