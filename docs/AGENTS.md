# docs/ — the user guide, pending decisions and the release channel

This repository follows the model in the root `AGENTS.md` ("Code is the
record"): the code describes the system, `AGENTS.md` files carry the rules the
code cannot show, and a page in `docs/` exists only while it describes work
that is not code yet or is written for the user. That decides what lives here:

- `docs/user/` is the user guide, in Finnish and English. It is the one
  permanent piece of prose about the product, and it changes in the same
  commit as the command it describes. `docs/user/AGENTS.md` has its rules.
- `docs/site/` holds the ADRs and plans still waiting for implementation, as a
  flat directory of Markdown pages with a glasspad manifest (below).
- `docs/DISTRIBUTION.md` is the maintainer's page for the binary release
  channel. Its marked region is regenerated by `/shipshape-dist` together with
  `dist-workspace.toml` and `release.yml`, which is what keeps it current.
- `docs/tools/` holds a retired HTML generator kept as frozen reference; its
  own `AGENTS.md` says why and what is worth reading in it.

Architecture descriptions, decision logs, landed ADRs, design and options
pages, benchmarks and a glossary used to live here and were removed once their
rules were in `AGENTS.md` files and the user guide had its own glossary. Do not
bring such a page back: put a rule that the code cannot show into the nearest
`AGENTS.md`, a plan or analysis into the issue it belongs to, and a term a user
meets into the user guide's glossary.

## ADRs

An ADR records one architectural decision while it is still work: from its
acceptance until its implementation lands. The analysis that led to it belongs
in its issue. When the implementation lands, the slice that lands it moves any
rule the code cannot show into the nearest `AGENTS.md` (`crates/AGENTS.md`, a
crate's own `AGENTS.md`, or a skill) and removes the ADR page, its audience
companions and their entries in `glasspad.yaml` in the same change. A partly
built ADR stays until the rest is built or explicitly dropped.

An ADR page has the Status, Date, Authors and Refines lines at the top and
Context and Decision sections. Some have two Finnish audience companions,
`<adr>-kirjanpitajalle` (for bookkeepers) and `<adr>-arkkitehdille` (for
architects): short summaries that open by saying the real decision is in the
ADR and that the companion decides nothing new, declared as `children:` of the
ADR in the manifest so they nest under it in the sidebar. Companions are
optional.

## Adding pages

A new page in `docs/site/` is a decision or plan still waiting for code. A
design that only explains how something was built is not a page; once built,
the code explains it. Every page has a place in the manifest `glasspad.yaml`,
which gives the directory its structure (title, grouped sidebar, titles,
optional per-page `desc`, one level of `children:` nesting) and holds no
content.

## How glasspad sees this directory

The pages are plain Markdown and read fine on GitHub, but the manifest is
validated by glasspad's scan, which is flat and strict:

- Only top-level `.md` and `.html` files plus `assets/` are published; every
  other subdirectory is ignored, so a new page goes at the top level of
  `site/`.
- A slug is the filename stem: lowercase `[a-z0-9-]`, starting alphanumeric.
  ADRs are `adr-3-fiscal-store.md`, not `ADR-3-…`, and audience companions are
  hyphenated (`adr-3-fiscal-store-arkkitehdille.md`) because glasspad does not
  parse a dotted stem. Two files with one slug are a hard error, as are the
  reserved names `_gp`, `_c`, `assets`, `api`.
- A symlink at the top level of `site/` or under `assets/` is a hard scan
  error. This file and its `CLAUDE.md` symlink therefore sit at `docs/`, one
  level above the space.
- Links between pages are relative slugs: `[x](adr-3-fiscal-store)`.

`glasspad build docs/site <out>` renders the space statically and is the
cheapest way to check that a change scans cleanly.
